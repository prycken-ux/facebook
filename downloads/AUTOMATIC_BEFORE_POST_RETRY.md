# 本地发布主程序的一次自动补发队列

入口：publish_new_with_comments.py；上传核心2.46；PUBLISH_WORKFLOW_VERSION=2.0-auto-retry-once。安装仅更新脚本，不开始上传、不调用旧13条补发、不重置旧发布和评论账本，不建立后台扫描或定时任务。

每次明确授权、确认实拍并通过主程序启动的新批次，按顺序执行：

1. 冻结本批没有任何旧发布记录的原视频及文案；保留同名非空 TXT，否则用已保存的统一文案。包括 fb10 十个公共主页，排除 fb16/fb18/fb21。
2. 先处理完整批首轮视频；某一目标出错先记录并继续。
3. 首轮结束后，仅自动补发本批可恢复的发布前失败一次。允许暂时的网络中断、上传未完成或按钮仍不可用、已确认的入口/话题建议遮挡、浏览器提前关闭、账号资料暂时占用等已识别错误。每次均重核身份、原文件完整指纹、配置及文案，不替换素材、不删除旧状态。
4. 自动补发机会在启动浏览器或选文件前写入 logs/automatic_before_post_retry_claims.json。即使中断、关闭浏览器失败或再次运行，机会不会重新发放；按视频完整任务编号判断，改名或换批次不能获得第二次自动补发。上传核心继续保留原尝试历史。
5. 成功、已点击 Post、待核实、已有成功线索、已经补发、仍有其他提交任务、登录/图片验证码/安全提示、文件或配置变化等都不自动补发。原失败和待核实记录保留给人工核实；不通过切换身份或重置保护来强行发出。
6. 再统一处理本批确认成功视频的指定评论，独立记录发送及刷新核验结果。评论失败不会导致视频重新发布。未保存确切视频链接的仍会跳过评论，不表示评论成功。
7. 控制台直接显示成功、发布前失败、待核实、未开始以及评论的文字名单。不生成本批CSV，不弹出记事本；JSON、文字和必要诊断包保留在 logs，供断点检查。旧13条脚本也取消自动弹记事本，但安装不运行该脚本。

队列必须来自明确标记 auto_retry_policy=recoverable-before-post-once-v1 的当天新批次，并且首轮已经处理完本批清单。不接收历史日期清单、人工补发清单或不明的失败列表，不猜选最新文件。发布后等待成功回执仍遵守核心三分钟上限。每批启动仍须明确指定当天日期，并确认该批素材的AI情况；不会因为安装了此功能就自行发布以后放入的素材。

人工核实后明确要求对某条旧任务再发，属于新的单独授权，不由此队列擅自执行。原10月31日的成功/待核实视频及其评论不会因安装自动重发或补记。

自动传回聊天的通道未接通；本更新只实现电脑本地的队列和文字汇总，不能自动给当前聊天添加附件或消息。

核心版本升级到2.46，使旧安装包在覆盖前因版本检查而拒绝降级，避免重跑旧指令时丢失新队列。安装后不修改原配置及既有发布/评论记录。

验证覆盖：首轮→一次补发→评论的顺序；成功/未知提交/安全验证排除；同任务跨批次及重启不重复；关闭浏览器失败仍消耗机会；实际核心 Post 意图先落盘与成功归档；文件/配置/文案变化；文本输出无CSV、无弹窗。合成浏览器测试不替代下一批真实 Facebook 页面验证。历史上限定10月31日的续跑CLI继续拒绝过期日期，不属于新通用队列入口。
