# Owner-assisted login diagnosis and continuation of the same fifteen-job grant

The user authorized manual login/verification checks after the last run stopped before upload for all fifteen targets. This entry checks only profiles fb09, fb17, fb37, fb38 and fb55 that still have a ready original job. It does not issue a new publication grant or reset retry claims. It preserves original successes, submitted outcomes, the other 46 unplanned new accounts and their comments.

For each account, a read-only background probe uses the original profile. If it fails, a visible browser opens from the same profile on about:blank before navigating to Facebook, so the existing launch checkpoint does not close the browser needed for the owner to finish the official login/verification. The console prompts for Enter to verify, R to reopen the mapped profile, S to skip, or Q to pause. No file is selected during diagnosis. No display-name or AI prompt is added.

A successful foreground owner check is followed by another background probe. If only background fails, the console explains the observed difference without assuming logout or a specific proxy/extension cause. The owner can select F to use minimized ordinary Chrome only for that account in this run, R to recheck, S to skip, or Q to pause. Conflicting/wrong owner evidence never enables fallback. Global browser settings are not changed. Windows launches in this selected mode use --start-minimized and SW_SHOWMINNOACTIVE; Chrome may still briefly show a window, and the owner can restore it if needed.

Both probes require the original unique c_user owner, the expected personal actor and the existing numeric or /me vanity-route verification. Cookie values, passwords, login markers and raw navigation query strings are not saved. The local diagnostic report contains only account, mapped target, safe status categories, times and the selected mode. It is at logs/nov14-fifteen-manual-session-diagnostics.json.

The existing PID lock recovery and batch locks prevent concurrent publication. Original Chrome sessions are closed gracefully, not killed. The interactive launcher inherits console stdin; the older closed-stdin background command must not be used for this manual step. After diagnosis, the original fifteen-job runner continues its existing durable grant with the approved per-account mode. Skipped/unverified profiles remain unstarted. Newly successful originals receive the previously approved comments through the original scoped comment flow.

Validation: eight local tests cover visible-window lifetime, Enter handling, background/foreground mode selection, explicit F fallback, conflicting owner refusal, safe network-error classification, Windows minimized flags and real-core continuation of fourteen targets with one skipped account, followed by a rerun with zero duplicate Posts. Five launcher tests cover active-lock refusal, rollback, date guard, fresh-process imports and the child entry. Browser/UI events are synthetic; the actual Windows sessions are checked when the user runs the command.
