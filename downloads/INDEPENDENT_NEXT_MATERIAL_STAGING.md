# Prepare today's next materials while an older publication continues

Run `start_stage_next_materials_20261114.py` from a separate PowerShell window. It caches a verified new standalone tool under `material-staging/tools/<code fingerprint>/`; it does not replace uploader modules, recover/remove upload locks, modify publication state or acquire the uploader's lock for preparation. The owner selects today's total source folder with the existing Windows folder picker.

Preparation reads a consistent account/config/reservation snapshot and uses the existing numeric account and target ordering: all registered targets and reserved profiles, including Pages, one naturally sorted MP4 per target. Completed material-distribution history excludes sources already allocated from the same total folder. Video/TXT/comment companions are copied to `material-staging/<Beijing date>/<source fingerprint>/videos/<account>/<target>/inbox`, with the originals retained. A separate immutable manifest, progress file and summary support resumption without reshuffling when the source pool changes. Live inboxes, account registration, publication/comment receipts and current distribution preferences are untouched. A per-stage OS file lock is independent from publication and releases if the stage process exits.

After staging, the window prints a safely single-quoted PowerShell import command, also saved as `导入指令.txt` in the batch folder. Run that command only after the original videos, comments and login checks have finished. Import takes the original global upload locks and checks for any other Python task from the same upload root/venv, so a live publisher between per-video lock intervals still blocks import. Process inspection returns only PID/name; it does not export command lines, credentials or environment. Inspection failures block import. No process is killed or lock forcibly removed.

Import rechecks target membership, previously bound owners, reservation generations and every staged file fingerprint. Existing pending slots may finish registration while preparation is running; that does not change their per-account allocation. Copy destinations use a dated/source-specific prefix and the original no-overwrite atomic copier. Existing video task records are not refilled. Import creates the normal distribution journal/progress/settings for later publication without posting or commenting. Completed reruns do not refill an archived file or reset later source preferences. New and old material remain separate.

Local validation: seven tests cover preparation with live upload locks, preservation of live material/config/state, import refusal for a live worker between job locks, actual 94-target import, no-overwrite/idempotent reruns, owner/file mutation, interrupted preparation with pool growth, registration completion and safe Windows process-query output. Three launcher tests cover actual separate child argv with an active upload lock, checksum refusal and preservation of an unknown cache. Windows dialog/process calls are simulated in the Linux tests; publication is never executed by this tool.
